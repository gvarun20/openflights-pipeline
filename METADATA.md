# Table & column dictionary — Open Flights Demo Warehouse

> **Purpose of this file:** quick reference for what each table means in this **student demo project**.  
> This is not enterprise data governance — just documentation so future-me (and markers/recruiters) know what I built.

**Who is this for?**
- **Non-technical readers:** read the table names and “Meaning” columns — ignore SQL types if unfamiliar.
- **Technical readers:** use with [Data model (Section 7)](DOCUMENTATION.md#7-data-model-star-schema) in DOCUMENTATION.md and `sql/schema.sql`.

**See also:** [README](README.md) (overview) · [live dashboard](https://gvarun20.github.io/openflights-pipeline/) (charts built from these tables)

**Database name:** `openflights_dw`  
**Schema style:** star schema (1 fact table + dimension tables)  
**Row counts (after ETL):** ~66,316 routes · ~7,698 airports · ~6,162 airlines

---

## Fact table

### `fact_routes`

**Grain:** one row = one route record from OpenFlights `routes.dat` (after FK filtering).

| Column | Type | Meaning |
|--------|------|---------|
| `route_id` | SERIAL PK | Surrogate key generated by PostgreSQL |
| `airline_id` | INT FK → `dim_airline` | Operating/marketing airline |
| `src_airport_id` | INT FK → `dim_airport` | Origin airport |
| `dst_airport_id` | INT FK → `dim_airport` | Destination airport |
| `equipment_id` | INT FK → `dim_equipment` | Aircraft type (nullable if unknown) |
| `codeshare` | BOOLEAN | `true` if codeshare flight |
| `stops` | INT | Number of stops (0 = direct) |
| `loaded_at` | TIMESTAMP | When the ETL inserted the row (demo audit column) |

**Notes for demo:**
- ~449 routes skipped because airline/airport IDs were missing from dimension files
- I did **not** deduplicate routes — this mirrors source data behaviour

## Dimension tables

### `dim_airport`

One row per airport from `airports.dat`.

| Column | Type | Meaning |
|--------|------|---------|
| `airport_id` | SERIAL PK | OpenFlights numeric ID (preserved from source) |
| `name` | TEXT | Full airport name |
| `city` | TEXT | City name |
| `country` | TEXT | Country name |
| `iata_code` | CHAR(3) | IATA code (e.g. ATL) — nullable |
| `icao_code` | CHAR(4) | ICAO code — nullable |
| `latitude` | NUMERIC | Used for map visualisations |
| `longitude` | NUMERIC | Used for map visualisations |
| `altitude_ft` | INT | Elevation in feet |
| `timezone_utc` | NUMERIC | UTC offset hours |

**Role-playing dimension:** same table used for both source and destination in `fact_routes`.

---

### `dim_airline`

One row per airline from `airlines.dat`.

| Column | Type | Meaning |
|--------|------|---------|
| `airline_id` | SERIAL PK | OpenFlights airline ID |
| `name` | TEXT | Airline name |
| `iata_code` | CHAR(2) | IATA airline code — often null |
| `icao_code` | CHAR(3) | ICAO code |
| `country` | TEXT | Airline home country |
| `active` | BOOLEAN | Active in OpenFlights registry |
| `valid_from` | DATE | SCD Type 2 — start date (future use) |
| `valid_to` | DATE | SCD Type 2 — end date |
| `is_current` | BOOLEAN | SCD Type 2 — current version flag |

**Demo honesty:** SCD columns exist for coursework design marks; I have not loaded historical versions yet.

---

### `dim_equipment`

Aircraft types from `planes.dat`.

| Column | Type | Meaning |
|--------|------|---------|
| `equipment_id` | SERIAL PK | Surrogate key |
| `iata_code` | CHAR(3) | Aircraft code (e.g. 320 = A320) |
| `aircraft_name` | TEXT | Full name |
| `category` | TEXT | Optional grouping (not always populated) |

---

### `dim_date`

Calendar dimension — **designed but not loaded** in this demo.

| Column | Type | Meaning |
|--------|------|---------|
| `date_id` | INT PK | Format YYYYMMDD |
| `full_date` | DATE | Calendar date |
| `year`, `quarter`, `month`, … | various | Standard date attributes for future schedule data |

**Why empty:** OpenFlights route file has no flight dates — I added the table to show I know how date dims work.

## Source files → tables mapping

| File | Target table(s) |
|------|-----------------|
| `airports.dat` | `dim_airport` |
| `airlines.dat` | `dim_airline` |
| `planes.dat` | `dim_equipment` |
| `routes.dat` | `fact_routes` |

## Known data quirks (good to mention in viva/interview)

| Quirk | What I did |
|-------|------------|
| Nulls encoded as `\N` | Parsed to SQL `NULL` in ETL |
| Orphan route IDs | Skipped (~449 rows) |
| Outdated airline entries | Loaded as-is; flagged via `active` column |
| No flight timestamps | No time-based analytics yet |
